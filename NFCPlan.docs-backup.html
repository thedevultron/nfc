“A digital operating system for physical businesses.”

We connect customers to businesses through NFC/QR touchpoints, then help the business manage the customer journey through websites, WhatsApp, bookings, CRM and AI automation.

The NFC product is Our door opener.

The software and automation are where the recurring revenue comes from.

A. Dynamic Database Parameters Over Code Forking

  • All merchant storefronts run from one single multi-tenant application.
  • URLs resolve dynamically: brand.in/c/:merchant_slug or custom merchant domains mapped via CNAME.
  • When a customer taps or scans, the PWA retrieves the specific merchant's JSON config (branding, live items, pricing, operating hours) from a central PostgreSQL database with Row-Level Security (RLS).

B. Agentic Onboarding Pipeline

Instead of manual vibe-coding for each client, AI agents act strictly as Configuration & Asset Ingestors:

  1. Data Ingestion Agent: Amir uploads the client’s physical menu (PDF/image) and brand assets. The AI agent extracts items, categories, variants, and dietary tags into structured JSON.
  2. Database Population: The agent validates the schema and inserts it into the unified database under the merchant’s tenant_id.
  3. Vision QA & Human-in-the-Loop (HITL) Staging:
  • The agent renders the staging preview across mobile viewports.
  • A vision model checks for visual bugs, overflowing text, or low-contrast buttons.
  • The Guardrail: For the first 20 clients, the system outputs an automated 3-screen visual validation summary. Amir or Aryan clicks "Approve & Deploy" before configuration flags go live in production.

The "Read-Only Bridge" Strategy

  1. Phase 1 (Safe Ingestion): Build read-only n8n endpoints that poll/ingest public or open webhook payloads from POS systems (e.g., Petpooja inventory sync). When a dish is marked unavailable on the POS, your platform mirrors that "Out of Stock" state instantly.
  2. Dashboard Manual Override ("Kill-Switch"): If a POS webhook drops or desyncs, the merchant dashboard has a master toggle: "Force Override POS", allowing the floor manager to mark items in or out of stock directly in 1 second.
  3. No Direct Writing: Payments and table bills are settled via standard payment gateways or at the counter. Your PWA handles menu display, guest interaction, review routing, and booking leads without risking the merchant's financial records.

4. Policy, Legal & API Compliance

A. Google Business Profile Review Integrity

  • The Rule: Google’s Prohibited and Restricted Content guidelines strictly ban Review Gating (routing low-star ratings away from Google while sending only 4/5-star reviews to Google Maps).
  • Compliant Implementation:
  • The user lands on a clean, compliant interface:
  • Primary Action: "Leave a Public Review on Google" (Opens the direct Google Review URL natively).
  • Secondary Action: "Talk to Management / Report Private Feedback" (Directs straight to a WhatsApp thread with the owner/manager).
  • No conditional star-filter modal precedes the Google review button. This protects the merchant's Google Business Profile from penalties or review removal while still offering a direct resolution channel for unhappy customers.

B. WhatsApp Meta Cloud API Structure

  • Separation of Costs: Do not bundle unlimited WhatsApp messaging into standard SaaS fees. Meta charges per 24-hour conversation window (categorized by Marketing, Utility, and Service).
  • Billing Architecture:
  • The client connects their own Meta Business Manager account with their credit card on file, OR
  • The client buys a prepaid message credit pack from your dashboard (e.g., ₹1,000 credit pack; your system debits actual Meta API costs + a 15% platform management fee).
  • Opt-In Guardrails: Reminders and follow-up templates are triggered exclusively when a customer explicitly requests a booking, views a catalog, or engages with the touchpoint, ensuring full compliance with Meta's spam policies.

9. Key Operating Principles & Guardrails

  1. Zero Codebase Forking: Every client is a row in a database, not a new repository or custom deployment. If an agent writes code for an individual client, the architecture has failed.
  2. Read First, Write Never (POS): Pull data from external systems; do not attempt to write transactional billing records to third-party POS machines. Always provide a manual override.
  3. Protect the Merchant's Google Asset: No review-gating scripts. Keep public review access open and transparent while providing a parallel private feedback channel for issues.
  4. Decouple Variable API Costs: Meta WhatsApp conversation costs must never erode baseline SaaS subscription revenue.
  5. Master Two Verticals First: Win cafes and salons in Pune before expanding into complex multi-stakeholder industries.
